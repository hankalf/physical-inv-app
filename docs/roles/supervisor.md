# SOP — Supervisor

**Role:** Supervisor  **Login profile:** *Supervisor — everything a supervisor can*  **Pages:** Dashboard, Cycle counts, Front bins, Not in Location, Teams & crew, Testing Suite, User guide  **Functions:** all but Settings

This procedure is for the senior supervisor whose login does everything except open
**Settings**: run the floor, read the numbers, approve adjustments, run the cycle programme,
the front-bin moves and the Not in Location list. It is a map of the three procedures that
make it up, with what is specific to holding all of them at once. Read it with:

- **SOP — Count Supervisor** for count day on the floor;
- **SOP — Inventory Control** for the numbers, the approvals and the exports;
- **SOP — Warehouse Jobs** for front bins, moves, Not in Location and the cycle programme.

## 1 — What this login can and cannot do

**Can**: everything on the Dashboard (progress, map, team plan, alerts, second counts,
adjustments, reports), Teams & crew (crew, teams, equipment rules, the counting plan),
Cycle counts, Front bins and the move desk, Not in Location, the Testing Suite, every
download, every approval, messages and SOS, raising second counts, the board note.

**Cannot**: anything under **Settings**. That is: create or close a count, change its
options and thresholds, upload the bin list or the inventory report, pair racking blocks,
register or reset scanners, choose which jobs the guns offer, the ERP file, backups, logins,
the site name, the Teams channel. An admin does those; section 2 is the list to hand them.

## 2 — Before a count: what to ask the admin for

Hand the admin this list a day ahead, filled in:

| Ask | Where the admin does it |
|---|---|
| Create the count, name it, make it the scanners' default | Settings → Getting started → Count session |
| Upload the bin list; pair the racking blocks | Settings → Lists & racking |
| Upload each system's inventory report, naming the system | Settings → Lists & racking → Inventory report |
| Thresholds: Recount over __ units / __ %, cap __; approvals on/off, threshold __ | Count session options |
| Pallet check: off / warn / strict; guided bins on; the map drawing | Count session options |
| Scanners registered, links opened, app installed, charged | Settings → Scanner screen |
| Jobs on the scanners: full count only for count day | Settings → Scanner screen → Jobs on the scanners |
| A trial run, if the crew is new; End the trial before the real start | Count session → Trial run |
| Teams channel test card sent | Settings → Advanced |

Then build the **counting plan** yourself (Teams & crew): teams, crew, aisles in order,
**Stagger**. Check the guided setup card with the admin until nothing is red.

## 3 — Count day, in one page

1. **Start of shift**: teams sign on (count, team number, every clock-in number, *Sign on &
   load list*); Team plan fills; the board on the TV.
2. **Watch**: Progress for pace, Map for coverage, Team plan for who has stopped, Alerts for
   SOS, Reports → Fix list for labels, damage and blocked bins. Walk the fix list while the
   team is nearby.
3. **Answer**: an SOS gets **Seen** first, then feet; a stopped-scanning alert gets a message
   first, then feet; messages carry instructions, not questions.
4. **Second counts**: keep the list moving while teams are on the floor; if it is hundreds
   deep after one aisle, the thresholds are wrong and the admin changes them now.
5. **Hand-back**: every aisle handed back, every bin counted or its absence written down,
   nothing open on second counts, the fix list walked, every gun signed off and on charge.
6. **The numbers**: pallet report status by status and by system, adjustments approved with
   reasons, the close-out checklist in the Inventory Control procedure. Tell the admin to
   **close**; after the close the MISSING pallets join the adjustments; approve or reject
   them; sit with the admin for the ERP file; export everything and the log.

## 4 — Wearing two hats: floor and numbers

Small sites give one person both. What to keep separate:

- **Do not approve adjustments while teams are still in those aisles.** A second count that
  changes a pallet clears its approval and the line comes back. Approvals are an afternoon
  job, after the floor is quiet.
- **Do not raise second counts on your own aisle's variances and then count them with the
  same team.** The gun prefers a different team for a second count; let it.
- **The log keeps the two apart for you**: it records who raised, who counted, who approved.
  An auditor reading it should see the same name only where there was nobody else.
- **A trial run is the time to rehearse the whole day** in two hours: sign on, count, SOS,
  second counts, approvals, the file. End the trial, then start for real.

## 5 — Between counts

- **Cycle counts**: today's batch, what is still open, coverage; counters sign on with a
  badge alone. One session for the year.
- **Front bins**: the front-placed list after a count, the move list built from it, the
  move desk (and the gun's Front2Back, with the pallet system framed on both).
- **Not in Location**: the ERP's lost pallets; any scan anywhere finds them; close the rest.
- **Teams & crew**: leavers off the crew, new badges on, equipment rules current.
- **Testing Suite**: twenty minutes with every new starter, and with everyone before a
  wall-to-wall. *What to practise* sets up the cycle count, a move and a Not in Location run.
